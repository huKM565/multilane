# Ghostlane CLI: 12 комнат на каждый профиль роутера

## Цель

На роутере Netis NX32U каждый выбранный профиль должен одновременно использовать 12 olcRTC-комнат и объединять их в один туннель. Профилей шесть: Германия и Финляндия, в каждой стране VK Calls 12x, Mamba 12x и SaluteJazz 12x. Текущее поведение по одной комнате на линию не устраивает пользователя.

## Текущее состояние

- Роутер запускает `ghostlane-cli 1.0.472` с шестью одиночными inline-линиями DE/FI.
- Движок обновлён до olcRTC `v0.15.1-0.20261118074214-d06694cb2e6a`.
- Russia-direct читается из `/etc/ghostlane-direct.rules` через локальный патч `DirectRulesFromFile`.
- Исходник CLI находится в `/home/hukm/ghostlane-src/cli`; это не git-репозиторий.
- Mamba 12 уже развёрнута на обеих ВДС. SaluteJazz сейчас имеет четыре комнаты, VK Calls — четыре на каждую ВДС.
- Панель Noctalia переключает шесть линий через существующий CGI.

## Подход

Многокомнатность реализуется внутри `ghostlane-cli`, без отдельного supervisor и без запуска графического приложения на роутере.

### Парсер

`links.Entry` получает bonding-описание. Парсер принимает существующий формат подписки:

- основная `olcrtc://` строка содержит первую комнату и видимое имя профиля;
- `##rooms:` добавляет остальные одиннадцать комнат с теми же provider, transport и ключом;
- `##bond-vless:` задаёт общий plain-TCP VLESS-вход на нужной ВДС;
- служебные `##group:` не становятся ошибочными строками списка.

Профиль без bonding-директив остаётся одиночным и работает без изменений. Неполный пул, неизвестный провайдер, повторяющиеся комнаты и VLESS не plain-TCP отклоняются с понятной ошибкой. Секреты не выводятся в `list`, `status` и журналы.

### Запуск пула

Daemon получает отдельный bond runtime:

1. Для каждой из 12 комнат запускается свой olcRTC runtime с отдельным loopback SOCKS-портом.
2. Все комнаты получают одинаковые Russia-direct правила из существующего файла.
3. Встроенный Xray создаёт по VLESS-outbound на комнату, каждый через её SOCKS, и объединяет их `roundRobin`-балансировщиком.
4. Xray предоставляет один aggregate SOCKS с авторизацией. Существующий sing-box front и TUN подключаются к нему без изменений.

Так сохраняются TCP и UDP, текущие probe, status, stored selection и TUN. Одна TCP-сессия остаётся на одной комнате; разные сессии распределяются между комнатами.

### Ошибки и восстановление

Для первой версии пул считается готовым только когда готовы все 12 комнат. Ошибка любой комнаты останавливает уже запущенные и применяет существующий retry/failover daemon. Если любая комната умирает после подключения, aggregate состояние сообщает об отказе и daemon перезапускает профиль целиком. Динамическое изменение balancers без reconnect не входит в объём.

Одиночные линии, VLESS, XHTTP и старые подписки сохраняют прежнее поведение.

### Роутер и панель

На роутере шесть профилей в том же порядке, что сейчас:

1. `DE · VK Calls 12x`
2. `DE · Mamba 12x`
3. `DE · SaluteJazz 12x`
4. `FI · VK Calls 12x`
5. `FI · Mamba 12x`
6. `FI · SaluteJazz 12x`

Каждый пункт панели явно показывает `12x`. CGI продолжает использовать номера 1–6. Текущий профиль определяется по `Selection`. Russia-direct и отсутствие Hysteria сохраняются, podkop остаётся установленным.

### Необходимые комнаты

- Mamba: существующие M1–M12 на каждой ВДС.
- SaluteJazz: автоматически создать J1–J12 на каждой ВДС через существующий anonymous `CreateRoom`.
- VK Calls: нужны V1–V12 на каждую ВДС. Сейчас известны только V1–V4; для каждой ВДС нужны ещё восемь постоянных ссылок. Существующий `CreateRoom` требует organizer token, которого в проекте нет. Повторять одну комнату под разными номерами нельзя.

Отсутствие новых VK-ссылок блокирует только запуск VK 12x, но не разработку и тестирование bonding.

## Проверка

- Unit-тесты парсера: 12 комнат, стабильные ID, отказ неполных и небезопасных пулов, отсутствие утечек.
- Unit-тесты Xray: 12 SOCKS-outbounds, 12 VLESS-outbounds, roundRobin, UDP и корректная авторизация.
- Daemon-тесты: запуск 12 движков, остановка при частичном отказе, reconnect при потере комнаты, неизменность одиночных линий.
- Полный `go test -race` для CLI и проверка ARM64-сборки.
- Живой роутер: каждый доступный профиль поднимает 12 отдельных процессов/сессий, статус `up`, TCP и UDP проходят, российские адресаты идут direct, остальные через ВДС.
- Потеря одной комнаты вызывает штатный reconnect без ручного вмешательства.
- Панель показывает страну, провайдера, `12x` и правильный активный пункт.

## Резервирование

Перед установкой сохраняются текущие `/usr/bin/ghostlane`, конфигурация и правила. Новый бинарник сначала проверяется из временного пути. Откат возвращает прежний бинарник и шесть одиночных линий.
